Section 3.4. Building the Reliability Block Diagram.

A reliability block diagram (R B D) is not the same thing as a functional or physical layout diagram, and conflating the two is a common source of confusion. The R B D's job is narrower and more specific: it shows the logical dependency between elements with respect to a stated failure definition, which elements have to survive, in what combination, for the system to still perform the function being analyzed.

Two structures cover most real systems:

Series structure: the failure of any one element fails the system. The system reliability is the product of the element reliabilities. In words: multiply the reliability of the first element by the reliability of the second, and so on through the last. Because every factor is less than one, each added element pulls the system reliability down. This is the default for most mechanical and electronic systems, because building in redundancy is expensive, especially for high-volume repeated parts. So most real systems are, reliability-wise, mostly series, even when they don't look that way physically.

Parallel, or redundant, structure: the system survives until all elements in the group have failed. The system reliability is one minus the product of the element unreliabilities. In words: for each element take one minus its reliability, which is its probability of failure; multiply those failure probabilities together to get the chance that every element has failed; then subtract that from one.

Interactive figure. A calculator and chart comparing the two structures. The horizontal axis is the number of blocks, from one to twelve; the vertical axis is system reliability. The series curve starts at the single-block reliability and falls with every added block. The parallel curve starts at the same point and rises toward one. With five blocks each at 0.99, the series system drops to about 0.951, roughly five times the unreliability of one block, while a parallel group of the same five would be essentially perfect.

The single most important, and most frequently missed, point about R B Ds: the same physical hardware can produce completely different block diagrams depending on which failure mode is being analyzed. A documented worked example makes this vivid: a free-wheel clutch system (two clutches in a shaft assembly) has exactly one physical layout, but two entirely different reliability structures depending on the failure mode considered. For the failure mode interruption (clutch stops transmitting torque), the system fails if either clutch fails, a series structure. For the failure mode clamping (clutch locks up when it shouldn't), the system only fails if both clutches clamp simultaneously, because either one clamping alone still allows the other to carry the torque, a parallel structure. The complete reliability diagram for the system is the series combination of both partial structures.

Interactive figure. A block diagram of the two clutches that redraws itself when the failure mode is switched. For interruption, the two clutch blocks sit one after the other in a single line: a series structure. For clamping, the two blocks are stacked on parallel branches. Two sliders set the chance of each failure mode per clutch. With five percent each, the chance of system interruption is about ten percent, but the chance of system clamping is only a quarter of one percent.

The lesson generalizes well beyond this specific mechanism: don't ask what's the R B D for this product, ask what's the R B D for this failure mode. A component that looks like a single point of failure for one failure definition can be part of a redundant pair for another. Skipping this distinction is how teams end up with an R B D that quietly overstates or understates system reliability without anyone noticing why the number looks wrong.

For systems too interconnected to reduce cleanly to series and parallel blocks, block diagram decomposition (breaking a complex network into series or parallel sub-blocks and reducing outward) and cut-set or tie-set methods (identifying the minimum combinations of element failures, or working combinations of survivals, that determine system failure) extend the same logic to arbitrary topologies, the mechanics of both are worked in Appendix A.

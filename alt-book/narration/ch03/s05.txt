Section 3.5. Interfaces: Where Half Your Field Problems Are Hiding.

Return to the statistic this chapter opened with. The formal name for the fix is straightforward to state and consistently hard to actually do: F M E A scope must explicitly include integration and interface failure modes, in both the block diagram and the analysis, not just the failure modes of individual parts and subsystems. The reason this is worth a dedicated section rather than a footnote is that interface failure modes don't announce themselves the way component failure modes do. Nobody is assigned to own the joint between two things, so unless someone deliberately draws it as its own block, it simply doesn't exist in anyone's analysis.

A documented audit finding shows exactly what this failure looks like in practice: a bicycle-brake D F M E A analyzed the brake lever, the brake pad, and the brake caliper, each as its own item, with its own functions and failure modes, but the interaction between them (how the lever's motion transmits to the pad, how the pad engages the caliper) was never described in the Functions column, and no failure mode addressing that interaction was ever analyzed. The individual components could each pass their own F M E A cleanly while the actual point of failure, the interface between them, was never looked at by anyone.

Interactive figure. Three boxes in a row: brake lever, brake pad, brake caliper. Each box is marked as analysed. The two connections between them are drawn as dashed red lines labelled: interaction never analysed.

The practical guidance that follows directly from this: interfaces can be analyzed either as part of an adjoining item's own analysis or as their own separate line items, but either way, the block diagram itself should explicitly show which interfaces are inside the scope of the analysis. If an interface isn't drawn as a block or a labeled connection, assume it isn't being analyzed, regardless of anyone's intention.
